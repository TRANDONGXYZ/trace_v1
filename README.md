# Trace: timeline whiteboard

React Flow whiteboard with browser-local diagrams and optional Cloudflare AI analysis. Public URL: **https://trace.trandongxzy.workers.dev**. The existing `trace` Worker serves both the website and AI API; no Pages project is required. Visitors need no account, login, database, Ollama installation, or running laptop server. See [DEPLOYMENT.md](DEPLOYMENT.md) for Windows deployment, configuration, updates, testing, privacy and free-tier limits.

## Start

For development, connect your Cloudflare Free account once with `npx wrangler login`, then double-click **start.cmd**. It starts the frontend and local Worker and opens **http://127.0.0.1:5173**. Cloud AI requests use the connected account's free allowance, including during local development. Keep the terminal open; Ctrl+C stops the local processes. The included portable Node.js runtime is used automatically. Public visitors simply use the public URL.

Alternatively, with Node.js 22.12 or later on your PATH:

```powershell
npm ci
npx wrangler login
npm run dev -- --open
```

## Use

- Type `/n`, then press Enter. Type receives focus first. Select a node type, enter the required text (labeled with that type), confirm Time (DD/MM/YY), and optionally enter a Description. Enter submits from Type/text/Time; in Description, Enter inserts a newline and **Ctrl+Enter** creates the node.
- Tab follows Type → event text → Time → Description. Time starts with today's computer-local calendar date each time the popup opens. The multiline Description accepts at most **500 user-perceived characters**, not words; emoji and accented characters remain intact. Stored text still uses the compatible `data.mistake` key.
- Nodes show type, event text and date; hover for full text/Description. All seven types use 160 × 96 layout boxes and retain their shapes/colors; Success stays circular. Vertical stacks leave a 32-unit clear gap. Existing nodes remain read-only.
- Click a node before creating another to connect them. Click empty canvas to create an independent node.
- Consequence requires a selected Mistake or Action. With a Mistake selected, Consequence is the default and only allowed successor type. Its date must be equal or later; an earlier date shows **“A Consequence must occur after the Mistake.”** without changing the diagram. Consequence cannot point to Mistake, Milestone or Success.
- Click an edge or its label to highlight it; click it again to clear the highlight.
- Drag between top/side ports to connect existing nodes. Multiple incoming/outgoing edges are supported. Mistake can only point to Consequence; Consequence can only receive from Mistake or Action and cannot point to Mistake/Milestone/Success. Different-date arrows normalize from earlier to later. Equal dates retain drag direction and use the same directed type rules as automatic creation. Self-links, duplicate directed links and invalid relationships are rejected.
- Click an edge or its label, then press Delete to remove only that edge. Nodes, other edges, and node positions remain unchanged.
- Double-click a node to highlight that node and every upstream node and arrow leading to it, including all paths that merge into it. Descendants and unrelated nodes stay unhighlighted. Click anywhere outside that chain to clear the chain highlight. Clicking within it keeps the chain highlighted.
- Drag empty canvas to pan. Ordinary wheel/two-finger scrolling pans using native scroll direction (the previous sign inversion is removed in both axes). With natural trackpad scrolling, fingers down/up/right/left move the canvas in that same direction. **Ctrl+wheel** and supported **pinch gestures** still zoom. Double-click never zooms; on a node it still highlights the incoming chain.
- Select a node and press Delete to remove **only that node and its incident edges**, immediately. Descendants, shared nodes, unrelated edges and survivor positions remain unchanged.
- **Ctrl+Z** undoes content changes; **Ctrl+Y** redoes them, including exact node/edge data and positions. New content after undo clears redo. Navigation/selection/no-ops do not enter history. Input/textarea shortcuts keep normal text editing. History lasts for the current page session only; undo/redo uses normal autosave.
- Escape cancels the creation dialog or clears selection/the typed command.
- Click **Mistake overview** to analyze recurring patterns. The public site defaults to the **Vietnamese + multilingual** Qwen3 embedding preset; an English preset is also available. Both use the same fixed Cloudflare embedding model with different calibrated browser grouping thresholds. The choice is remembered locally. Larger, darker bars and larger counts emphasize frequency. Expand **View occurrences** for original text, Description and dates. Close the overview or press Escape to return to the unchanged diagram.
- **Recent progress** shows recorded counts for adjacent two-month periods, recurring date ranges, increasing/new categories, achievements and upstream Actions, blocked situations and attempted Actions, and consequences. **Explain recent patterns** optionally analyzes deeper psychological motivations shared within recurring Mistake clusters. Results distinguish model summaries of cited evidence from uncertain psychological hypotheses. **Cancel**, Close overview and Escape cancel the active request and suppress late results; cloud inference cancellation is best effort.

The diagram saves automatically to this browser's localStorage **3 seconds after the latest content change**. A small checkmark confirms a successful save and disappears when content changes again. Reopening the same origin/profile restores nodes, edges and associated data. Older layouts reflow for taller cards while retaining text, dates, IDs and relationships; restoration neither writes storage nor creates history. The next content save records the current layout marker so later reloads preserve exact coordinates, including deletion survivors. Panning, zooming, selection, highlighting and cancelled forms do not save or reset the timer.

Storage is local to the browser profile and website address (including the port). The public URL cannot automatically read diagrams from the old localhost origin; that previous data stays at its old address. Clearing browser site data removes the saved diagram. No cloud database or diagram backup is used. Only relevant text is sent to Cloudflare for requested AI analysis, and the backend does not save diagram content. If browser storage is unavailable/full, the diagram remains usable and the checkmark does not confirm unsaved changes.

## Optional local-only Ollama development

The default development and production workflow uses Cloudflare. To retain the previous local-only workflow, run `npm run dev:ollama`. The following model/resource notes apply only to that explicit mode. Start Ollama and install its Vietnamese-capable models once:

```powershell
ollama pull embeddinggemma:300m-qat-q4_0
ollama pull qwen3.5:2b
```

The embedding models and behavioral analysis model are installed on this laptop. For the optional English-only embedding model, run `ollama pull all-minilm:22m`. Semantic clustering calls `http://127.0.0.1:11434/api/embed`; behavioral analysis and optional explanations use the same local Ollama service's `/api/chat`. None uses a cloud API or a new application server. Ollama's default loopback origins support the local website. If a model is missing, the overview gives its specific pull command. Reopening or changing models retries clustering while leaving the diagram unchanged.

**Models:** The default [EmbeddingGemma 300M QAT Q4](https://ollama.com/library/embeddinggemma:300m-qat-q4_0) is a quantized multilingual embedding model with a roughly **239 MB download**, trained on 100+ languages and tested here with Vietnamese paraphrases. Its 768-dimensional embeddings use Google's recommended `task: clustering | query:` prefix from the [model card](https://huggingface.co/google/embeddinggemma-300m). The optional [MiniLM 22M](https://ollama.com/library/all-minilm) has a roughly **46 MB download** and 384-dimensional embeddings, for English-only data. Download sizes are not runtime RAM estimates. Only the selected model is requested, and switching cancels the previous analysis.

Both models encode Mistake and Description; long fields are split into short chunks and their normalized vectors are averaged by chunk length, so Description is not silently discarded. Vietnamese accents are preserved. Only nodes whose type is Mistake enter semantic mistake clustering; the progress report also reads Success, Milestone, Blocked, Consequence, and connected Action/other context nodes. Each Mistake node counts once, including identical entries on different dates.

Normalized embeddings are compared with cosine similarity. Ordinary observed-behavior descriptions retain model-specific thresholds: **0.925 for EmbeddingGemma** and **0.58 for MiniLM**. Whole-record similarity alone can confuse a shared activity with a shared motivation: the supplied Vietnamese performance examples score about 0.844, whereas the incorrect-technique example and a missing-instruction counterexample score about 0.951. Lowering the whole-record threshold would therefore merge the wrong examples.

When at least two unique records state causal or priority context in English or Vietnamese, local `qwen3.5:2b` analyzes each of those records independently. It extracts a source-quoted priority, an approximate behavioral description, and a mechanism such as overvaluing a goal, missing knowledge, recording errors, or choosing recovery. Quoted passages must exist in the original Mistake/Description text; unsupported, malformed, or truncated profiles are rejected. Profile extraction precedes classification in the output schema, reducing premature topic-based judgments. The model does not decide whether every pair is the same, and no performance-specific keywords define cluster membership.

Two profiled records with different mechanisms cannot merge. Overvalued goals also require matching semantic priority domains: achievement/performance, approval/acceptance, control/certainty, comfort, or material gain. These are classified from the stated motive, not matched keywords. This matters because even short embeddings of achievement and displeasure can be nearly as close as two achievement paraphrases. Compatible profiles then compare embeddings of their source priorities (for overvalued goals) or behavioral descriptions, at **0.85 for EmbeddingGemma / 0.65 for MiniLM**. Unlisted priorities use a stricter **0.95** threshold rather than becoming a catch-all group. Unspecified mechanisms retain the conservative whole-record threshold. Entries without reported causal context retain observed-behavior matching rather than an invented motivation. Unsupported profiles and exceptionally long causal entries remain visible as unclassified singletons, without being cached as valid causes or erasing other groups. Complete-link clustering requires every cross-group pair to be compatible and retains strongest observed matches, preventing a single ambiguous record from bridging unrelated causes. [Sentence Transformers describes threshold-based agglomerative clustering](https://www.sbert.net/examples/sentence_transformer/applications/clustering/README.html). The displayed label remains an original member's text, not a model-generated factual claim. Original occurrences remain available; these model-assisted groupings are approximate, not confirmed diagnoses of a user's motivations.

**Resource limits:** Analysis runs on opening the overview, not while panning, selecting, or editing the diagram. Each request asks for CPU execution (`num_gpu: 0`), two CPU threads, a 512-token context, and at most eight short inputs. The embedding token batch is 512 because smaller token batches can reject or truncate individual input sentences. Requests are sequential, with a browser lock coordinating tabs where available. `keep_alive: 0` releases this model after each batch; no other model is explicitly stopped and no global Ollama settings are changed. See the [embedding API](https://docs.ollama.com/api/embed) and [Ollama memory-management FAQ](https://docs.ollama.com/faq#how-do-i-keep-a-model-loaded-in-memory-or-make-it-unload-immediately).

Content-specific embeddings are cached in separate localStorage entries for each model: up to 64 multilingual vectors or 128 English vectors, keeping their storage budgets comparable. Old MiniLM vectors are never reused as multilingual embeddings, and cached dimensions are checked. Identical content shares an embedding; zero mistakes or a single unique mistake needs no model call. Closing the overview cancels further work. The feature still shares CPU and system RAM with other applications; on a memory-constrained machine Ollama can queue requests or unload idle models under its own policy. These limits reduce contention without guaranteeing that another local model will never be affected.

Behavior profiles use the already-installed `qwen3.5:2b`, CPU-only, two threads, a 4096-token context, at most 192 generated tokens, and thinking disabled. Its installed Q8 weights occupy about 2.7 GB on disk; runtime RAM is additional. The smaller models tested here were unreliable at distinguishing the Vietnamese causal examples from counterexamples. Only one unique record is analyzed per request, rather than quadratic pairwise generation, and up to 128 full-content/model-version-specific profiles are cached locally. Each model request unloads afterward (`keep_alive: 0`); the shared queue prevents this app from loading embedding, behavioral, and explanation models simultaneously. The first uncached causal analysis can take tens of seconds per record on CPU. No other application's model is explicitly stopped, and no global Ollama settings are changed.

## Recent progress and explanations

**Period definition:** Two rolling calendar-month windows end on the computer's local calendar day, including today. The exclusive end is tomorrow's calendar date. Subtract two calendar months to get the recent start, then subtract two more from that boundary to get the preceding start; each subtraction clamps to month end. Windows include their start and exclude their end, with no overlap or gap. For 8 November 2026, the ranges are **9 September–8 November** and **9 July–8 September**. For 30 April 2028, the ranges are **1 March–30 April** and **1 January–29 February**. Dates are shown in the report. Older/future nodes stay on the whiteboard and in all-time clusters but do not enter period totals.

The app computes totals and differences for Mistake, Success, Milestone, Blocked, Consequence, and combined Success + Milestone directly from the records. Semantic mistake clusters are shared across the periods; rows show recent/prior occurrence counts, increases/decreases, new-in-comparison types, and recent first/last dates. “Recurring” means at least two recent occurrences. “New in comparison” means no occurrence in the preceding window; it does not mean the mistake has never occurred in the user's lifetime. All-time cluster cards also show first/last dates. Cluster membership is approximate; counts and dates are calculated from its actual members.

Recent achievements and blocked situations show their original text and descriptions, plus recorded directed paths from upstream Actions, including older Actions and paths through intermediate nodes. Merging paths deduplicate Actions; unrelated/downstream Actions and backward-date edges are excluded. Equal-date arrows retain their recorded direction. These paths show recorded associations, not proven causation. A missing path is explicitly reported. Recent consequences retain all original entries and a direct period-count comparison.

**Optional explanations:** The public site's **Explain recent patterns** button uses the existing Worker's same-origin API; explicit Ollama mode labels the same action **Explain recent patterns locally** and uses `qwen3.5:2b`. Analysis is per recurring Mistake cluster, with at least two recorded past/present members and recent activity. It reads all relevant Mistake/Description fields, including older cluster history, to suggest one shared psychological/behavioral hypothesis rather than repeat immediate causes for individual events. Vietnamese evidence requests Vietnamese output. Deterministic counts, dates and connected paths remain available independently.

Requests are serialized across the app/tabs. Large clusters use bounded collective evidence batches and one final hypothesis, without silently dropping long fields. Short R1/R2 references map exactly to original mistakes; a displayed result must cite at least two distinct in-cluster records. Unrecognized references, malformed output and incomplete generations are rejected. Model summaries and possible motivations remain explicitly unconfirmed; no output is written into the diagram. Cloud limits, server-side safeguards and privacy details are in [DEPLOYMENT.md](DEPLOYMENT.md).

Up to 32 completed cluster explanations are cached by exact evidence/model/prompt version. Cloud results also persist locally under hashed keys, reducing repeat inference across reloads. Missing evidence yields no assumed cause; an invalid cluster response does not discard other valid results. Cancel preserves completed results and aborts active/queued work. Ollama streams are disconnected and request `keep_alive: 0`; cloud cancellation is propagated to the AI binding without promising immediate GPU release. Diagram autosave, selection and viewport behavior remain separate.

## Implementation decisions

- Event calculations use UTC calendar arithmetic to avoid daylight-saving errors. The form's current-date default uses the computer's local calendar date. Two-digit years mean **2000–2099**. Invalid dates are rejected.
- Without a selection, a duplicate date retains ordinary stacking: 24 px above the highest existing node on that date, at its horizontal coordinate, with no automatic connection.
- With a selection, duplicate-date placement takes precedence for every permitted type. With no outgoing edges, use the selected row and existing horizontal spacing (264 units minimum for the same date), moving to a free slot if needed. With outgoing edges, leave a 32-unit clear gap above the **highest outgoing destination**; creation order breaks height ties. When dates match, use that destination's column; otherwise keep the new date's column and use the destination's height. Manual outgoing edges count; deleted and incoming-only edges do not. Occupied stacking slots move further upward with the same gap.
- Selected creations keep their automatic connections and type restrictions. Equal-date arrows point from selected to new and display zero days; manual equal-date links retain drag direction with the same type eligibility. Different-date chronological normalization remains unchanged. Earlier Consequence creation from Mistake is rejected.
- Creating an earlier event places it to the left (and below when both axes apply), and the arrow points **from the new event to the selected later event**. Different-date Consequences retain this behavior. A creation that would violate the connection-type restrictions is rejected without changing the graph.
- The selected node remains selected after creation. Click empty canvas to stop creating connections from it.
- With no node selected, the reference is the existing node with the **closest strictly earlier date**. Future dates are excluded even if their absolute time difference is smaller; ties on the same predecessor date use the first-created node. No edge is created. If no earlier event exists, a new independent earliest anchor uses the axes' extrapolated date, with no later-node reference. Explicit selections and same-date stacking retain their separate rules.
- Both axes retain nonlinear growth: `90 × ln(1 + elapsedDays / 14)` canvas units. The horizontal base remains 264: 160 of node width, 64 of label space and two 20 gaps. Vertical base spacing is 128: 96-unit cards plus a 32-unit clear gap. Row centers, collisions, edge endpoints/labels and rulers all use the taller geometry.
- Dates have base horizontal columns; selected same-date creations can add horizontal offsets within their date. A chronological constraint solver calculates the minimum column positions that preserve date order, the requested reference spacing, connected-edge label room, and same-row node clearance. Later dates clear the entire earlier date's span. Branch collisions use the nearest available vertical lane when that move agrees with chronology. If the move would push an event above a future event or below an earlier event, the solver instead adds horizontal clearance between those dates and keeps the reference-based height. Adding an earlier/intermediate date can automatically reflow columns to preserve chronology; users cannot drag or edit any node. The first-created surviving node stays anchored. These necessary layout constraints can increase spacing above the nonlinear minimum; different orthogonal paths cannot have lengths determined by duration alone while also obeying the required row and branch placement rules.
- Vertical chronology is solved using groups of **same-row connections and date stacks**, including the explicit height relationship to a selected node's outgoing destination. Those equalities retain their row coordinates and stack gaps. The requested placement above a different-date destination takes precedence over ordinary vertical chronology for that stack; horizontal chronology remains intact. Diagonal edges are minimum-spacing constraints, so a connected May destination remains free to move upward when March or April is inserted before it. A complete connected cluster is never treated as one fixed vertical shape. Later groups move upward as needed to preserve chronological order, predecessor spacing, and clearance; an unrelated edge elsewhere never disables this calculation.
- Day labels apply below one calendar month; month labels start at exactly one calendar month; year labels start at exactly one calendar year. Calendar anniversaries clamp to month end (31 Jan → 28 Feb). Fractional months/years use the fraction of the actual next calendar period and display up to two decimals. Hover a label for the exact elapsed day count. Labels use two lines.
- Automatically created upward edges leave the source at its top, turn right through a rounded corner, and enter the destination from the left. Their labels use available space along the horizontal run, avoiding shared-trunk label collisions; blocked runs use free space on the vertical segment. Manual edges follow the chosen endpoints with rounded turns; those endpoint choices persist through later automatic layouts. Manual labels also seek free straight segments so a newly added Consequence does not cover them. Connecting existing events does not reposition nodes. Highlighted edges render above nodes and other edges.
- All seven node types use the existing layout footprint and show selection with the same opaque 3 px blue SVG stroke. Success is a true circle, and side connection points for the circle and triangle meet their visible outlines. No clipped selection outlines or shadows are used.
- Axes remain at the left and bottom viewport edges. Their first-of-month coordinates receive exactly the same viewport translation and zoom as the graph. Each month represented by events has exactly one label per axis; offscreen markers are clipped.
- Horizontal month markers use the **actual date columns**, interpolated at the first day of each month. No synthetic offsets are added to the ruler. Every node center lies within its calendar month interval, including nodes inserted out of chronological order. A continuous logarithmic extension locates month starts outside the existing event dates.
- Selected duplicate-date nodes contribute their horizontal and vertical span to the rulers. Interpolation toward a later date starts at the end of the preceding date's span, keeping month-end nodes before the next month's single marker.
- The vertical ruler uses its **own actual y coordinates** from the first surviving event and vertical branches. Ordinary horizontal row connections and unselected equal-date stacks do not advance vertical time and do not introduce displaced vertical anchors; selected duplicate-date nodes contribute their span as described above. If branches revisit the same vertical band, a chronological envelope retains actual later branch positions rather than inventing marker offsets. First-of-month references interpolate between these vertical anchors; the January 12 branch is above January 1's marker, with December below. Both rulers receive the same pan/zoom transform as the canvas. Horizontal date-column growth cannot affect vertical marker positions.
